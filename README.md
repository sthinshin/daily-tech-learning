# 每日技术学习教练

## 定位

面向后端开发求职者，根据实际学习记录提供知识讲解、逐题复习、答题反馈和题库维护的 Skill。

求职技术栈与算法练习语言分别配置：你可以准备 Java 后端面试，同时用 C++ 刷题。支持按多语言方向组织学习，不代表内置了所有语言的完整题库。

## 核心能力

- **讲解知识**：先给结论，用日常生活类比、图表和具体例子解释概念。
- **逐题复习**：每日默认根据学习内容准备5道主问题，结合到期复习和薄弱点，一次只问一道。学习者明确指定题量时按其要求执行，作答后提供参考答案与反馈。
- **记录进度**：区分独立回答、提示后答对、代码运行与平台通过，保存真实学习事实。
- **按语言讲算法**：参考[代码随想录Hot100](https://programmercarl.com/hot100/)的对应题解，优先选择档案中算法语言的代码版本，例如Python对应Python3。回答附具体题目链接，并给出助手理解后重新组织的思路、过程演示、代码解释、复杂度和边界分析。
- **维护题库**：整理截图、文字和链接，检查重复、记录来源，区分可用题与待核验题。

执行入口见 [SKILL.md](SKILL.md)，详细规范按任务从 `references/` 读取；根据实际会话归纳改写的交互演示见 [学习示例](examples/learning-session.md)。

## 快速开始

1. 按所用工具的 Skill 加载方式加载本目录，技能名称为 `daily-tech-learning`。当前目录为发布准备目录；正式安装时技能文件夹建议命名为`daily-tech-learning`，包含本目录的完整公开文件。尚未完成安装验证或跨平台行为验证，本文不提供未经验证的安装命令。
2. 指定个人学习目录。完整记录流程需要助手能够读取、写入这个目录；查询外部来源时需要相应联网能力。
3. 告诉助手你的目标技术栈、算法语言、当前基础与近期卡点。时区用于安排复习日期；面试日期和每日时长可暂不填写。
4. 助手按需从模板创建缺失文件，保留已有记录。仅询问一个知识点时，不必先完成全部配置。

首次使用可以这样说（将目录替换为你自己的位置）：

> 请使用 daily-tech-learning，将记录保存在我指定的学习目录。我准备 Java 后端面试，目标技术栈是 Java 和 Spring Boot，用 C++ 刷题。我是初学者，最近学了 MySQL 的 LEFT JOIN，容易遗漏没有匹配结果的行。我的时区是 Asia/Shanghai，请用中文先问一道基础复习题。

配置中的 `profile.target_stack` 保存求职技术栈，`profile.programming_language` 保存算法语言。目标技术栈不会自动计为已学内容。

## 使用方式

| 需求 | 可以这样说 |
|---|---|
| 学知识 | 用生活例子解释数据库索引，再问一道理解题 |
| 复习 | 根据已学内容出3道题，一次一道 |
| 算法题解 | 按我配置的Python，参考代码随想录讲解两数之和 |
| 看代码 | 检查这段C++代码的边界问题，并解释原因 |
| 更新题库 | 把这张截图里的题加入题库，保留来源 |
| 报进度 | 今天学了事务，但隔离性还不熟 |
| 收尾 | 今天先到这里，请保存进度 |

算法题解可以这样请求：

> 请参考代码随想录Hot100，按我的算法语言解释这道题。回答附上对应题目的链接，并用你理解后的方式说明思路、演示一个输入、解释关键代码与复杂度，不要只转贴网站原文。

例如“两数之和”应链接到[具体题解页面](https://programmercarl.com/hot100/0001.two-sum.html)，而不只给Hot100首页。实际题解须先读取对应页面；网站原有语言实现、基于思路改写的实现和独立解法分别注明。用户只要提示或正在答题时，不提前输出完整答案。

典型流程为：读取进度 → 选题或讲解 → 等待回答 → 给参考答案与反馈 → 保存记录 → 继续或收尾。可以随时要求直接给答案、调整难度或只讲解不测验。

只要求更新题库时，不自动开始测验。单纯工作修复或代码交付，不强制进入学习流程。

## 掌握度

| 状态 | 依据 | 后续 |
|---|---|---|
| 🔴 未掌握 | 核心理解有误，或暂时无法回答 | 补基础后再练 |
| 🟡 待巩固 | 依赖提示、回答不完整或实现不稳定 | 安排独立复测 |
| 🟢 当前考点已掌握 | 能独立解释、实现或应用 | 根据表现延长复习间隔 |

**每日题量：**默认5道主问题，用户要求3道就准备3道；同日继续时接续未完成计划。纠错追问默认不占主问题名额，但用户限制总提问次数时也计入。单独解释知识、更新题库或结束学习不另启动5题，用户提前结束时不强制补满。这是交互中的计划，不是后台定时出题。

**本轮追问规则：**红色先纠错，再围绕同一知识点追问一道；绿色反馈后停止该知识点的自动追问，转到下一考点或收尾；黄色按具体缺口处理，讲解后答对不要求继续练到绿色。用户要求跳过、结束或限制总题数时优先遵从。这里调整的是本轮出题，未来到期复习仍会安排。

没有答题证据时标为待验证。复习参考学习后第1、3、7、14天安排，并根据表现调整。题库收录、看过讲解和计划学习都不等于已经掌握；单个考点答对不代表整章掌握。

## 能力边界

- 跨聊天接续依赖已保存文件，不保证取得其他聊天全文。无法写文件时会提供摘要，并说明尚未持久保存。
- 默认来源包括 [interview_note](https://github.com/vaynedu/interview_note) 和 [小林面试总目录](https://xiaolincoding.com/interview/)。**小林来源适用于总目录列出的全部技术面试模块**，包括语言、数据库、网络、操作系统、消息队列、分布式、系统设计及工具等；根据学习者技术栈和已学范围选题。
- **适用范围与离线缓存范围不同**：当前小林随包题目缓存只有MySQL。其他模块通过总目录按需访问与核验；没有缓存不意味着该模块不受支持，也不意味着已全量采集。Java后端与LEFT JOIN快速开始示例只是一个使用场景。
- 来源索引不等于已审核答案库；具体结论需核对适用产品和版本。本包未提供自动采集脚本，不承诺后台更新。
- 算法参考源为[代码随想录Hot100](https://programmercarl.com/hot100/)，按题号和题名定位页面，再选择对应语言版本。本次明确指定的语言优先于档案，求职技术栈不替代算法语言。页面或语言缺失时会说明；自行改写与网站原有代码明确区分。当前按需联网读取，不提供全量题解缓存，也未验证全部语言版本。
- 图表效果取决于使用环境；不支持交互或Mermaid时，改用表格与编号步骤。
- 定时提醒需要额外工具与实际注册；技能加载不代表提醒已经启用。
- 学习示例根据实际会话归纳改写，属于使用演示，不是逐字记录或独立验收报告；示例中的既往掌握情况不能导入新用户档案。
