# 复习、反馈与学习记录

与[技能入口](../SKILL.md)配合使用。只在处理相关任务时读取；文中学习数据路径均相对于用户学习目录。

## 每日题量与计划接续

- 当学习者开始当天学习、请求每日复习，或汇报进度后进入每日复习时，未指定数量则默认准备5道主问题；“给我出题/模拟面试”未指定数量时同样默认5题。学习者明确指定数量、主题、难度或展示方式时，以其本次要求为准。
- 根据已记录的当天/近期学习内容选择题目，结合到期复习和薄弱点；算法与八股比例按实际学习内容安排，不强制分配未学领域。缺少学习记录时先确认已学范围，不凭空凑5题。
- 5题是主问题计划数量，不代表一次展示5题。默认一次一道；红色纠错追问归入原主问题，不占主问题名额。明确限制总提问次数时，追问也计入上限。
- 同一天再次进入学习时，先查看已有计划和完成情况，接续未完成部分；已结束的计划不自动重新开启。用户明确要求加练、新一轮或调整题量时再创建或调整计划，不把用户提前结束的计划强行补满。
- 单个知识点解释、代码局部问题、单纯题库入库和学习结束确认，不触发额外5题。用户只要一道理解检查时遵从。
- 在需要跨聊天接续时将计划保存为`active_review_plan`，记录日期、目标主问题数量、主题、实际完成的主问题及状态。计划不计为已学；不要用包含追问的review_sessions总条数代替完成主问题数。已有文件保留其字段与历史，不为应用默认题量重写旧计划。
- 当已学范围不足以形成5个不同考点时，明确说明并减少实际题量；不得重复追问本轮绿色考点或加入未学内容来补足数量。
- 每日指用户所在时区的日期和当前交互，不表示无人值守生成、发送或提醒。长期复习日期算法保持不变。

### 计划记录字段

空白模板的`active_review_plan`与`pending_question`为null，表示尚无计划/待答题，不是缺失配置。开始计划后可按下列字段保存，兼容旧记录已有字段，不覆盖历史：

- `active_review_plan`：`date`、`status`、`question_count`（目标主问题数）、`planned_topics`、`completed_main_question_ids`、`skipped_main_question_ids`。本轮主问题使用唯一实例ID；不能仅用可重复改编的题库ID计数。
- `pending_question`：`main_question_id`、`question_id`（自编未入库时可为null）、`question`、`is_followup`、`status`。追问沿用原主问题实例ID。
- 完成主问题不等于掌握。追问结束后才将该主问题计为完成；跳过单独计数，不能当作答对。中途结束保存未完成状态。用户显式限制所有提问次数时另记录`total_question_limit`与`asked_question_count`，每次实际提问含追问均计数。
- 新建计划前，将旧计划归档到按需创建的`review_plans`数组；只保存计划事实，不将计划主题写成学习完成。当前题已回答或用户结束时清空待答状态或明确标为已回答/取消，不误当待答题恢复。

## 反馈与复习安排

| 评估 | 判断依据 | 后续处理 |
|---|---|---|
| 红色 | 核心机制错误，或暂时无法作答 | 补前置概念、缩小问题，尽早再复习 |
| 黄色 | 回答不完整、依赖提示、纠错后答对或实现不稳定 | 保留首答与纠错表现，安排独立复测 |
| 绿色 | 在当前考查范围内能独立解释、实现或应用 | 逐步延长复习间隔，不外推为整章掌握 |

参考学习后第1、3、7、14天安排复习，根据实际表现调整；逾期项以今天实际复习情况重新安排。没有作答则不新建掌握结论。

学习者每次回答后，先判断正确、部分正确或错误并指出依据，然后明确给出本题的正确答案或参考解法及简短解析，即使首答正确也要展示答案。对照用户回答说明差异；SQL题给出正确SQL或查询结果，算法题按题目要求给出正确思路或代码，理论题给出准确结论与适用条件。有多种有效解法时接受等价答案，不把参考解法当成唯一答案；存在不确定性时明确说明并查证，不编造“标准答案”。随后用“掌握程度 / 卡点 / 下次复习”简表记录。答案在作答后展示，不提前泄露；是否追问按下文“本轮题目的追问与结束”执行；每次仅一道，且不提前给出追问题的答案。

## 本轮题目的追问与结束

本节控制同一轮学习中的题目推进，不修改上述长期复习日期规则，也不改变技能何时被加载。

| 本轮当前考点评估 | 当前轮次动作 |
|---|---|
| 红色 | 先给参考答案、解释核心错误，再换例子或降低难度，围绕相同知识点追问一道，等待回答 |
| 黄色 | 按具体未解决的缺口决定是否追问；讲解后已答对且没有新的缺口时可转下一题，保留黄色并安排长期复测，不强求本轮变绿 |
| 绿色 | 给简短参考答案与依据，保存记录后停止自动追问相同知识点；有剩余计划题则转到其他知识点，否则收尾 |

- 每次追问后依据实际回答重新评估。仍为红色时继续解释并缩小到该考点的前置概念，逐次提问；不能机械重复原题，也不能一口气展示多个追问。
- 绿色后不得以“再确认一下”、换数字、边界变式或重复解释后理解检查等方式继续自动考同一考点。其他知识点可以继续，后续日期到期复习仍照常安排。
- 用户主动要求同考点继续练习时可继续；用户要求跳过、暂停、结束或指定严格题数/时间上限时优先遵从，即使仍为红色也保存当前结果并停止相应追问。
- 默认将纠错追问归入原题，不占预先约定的不同主题主问题名额；若用户明确限制总提问次数，则追问也计入，不越过上限。
- 不能为了结束追问而把提示后答对直接评为绿色；保留独立程度与判断依据。尚未作答时不预设红色或绿色。

## 记录与每日复盘

- 使用现有 JSON 结构，写入前重新读取，保留其他历史与未知字段，避免覆盖新记录；写入后验证 JSON 可解析。
- `study_log`：日期、题目或主题、实际完成情况、是否独立、耗时（仅用户提供）、卡点和下一步。
- `review_items`：知识点、掌握程度、判断依据、最近学习/复习日期、下次复习日期。匹配现有项目后更新，避免无意义重复。
- `review_sessions`：实际问题、用户回答、反馈和判断依据；来源于题库时附 `question_id`。保留首答与提示后表现的区别。
- 用户自评与实际答题表现分别注明；未知字段留空，建议或已展示答案不记成完成。
- 收到进度或答题后，在本轮结束前保存必要摘要。无法保存时明确说明，不宣称记录成功。
- 每日总结用“项目 / 今日完成 / 卡点或下一步”简表，最多算法、八股、复习三行，缺失信息标注待汇报。

## 每日学习收尾：累计掌握与鼓励

- 触发：完成约定的本轮学习/复习问题并反馈最后一题后，或用户明确说“今天学完了”“先到这里”“结束复习”时执行。中途结束也可以收尾，但如实注明未完成项。不要每答一题就宣布当日完成；单纯修改Skill或更新题库不触发学习收尾。
- 先保存本轮真实表现，再读取最新 `review_items` 与相关 `review_sessions`，展示“截至今日的掌握概览”，包含此前累计成果，而非只有今天内容。
- 只将有实际答题依据、最新评估为绿色的具体知识点列入“已掌握”；黄色列为“待巩固”，未知/只有自评的注明“待验证”。同一知识点有重复或冲突记录时按最近且范围匹配的实际证据判断，不用旧绿色覆盖新的错误；不把子知识点掌握扩展成整章掌握。
- 使用简洁彩色卡或带🟢🟡标识的表格，按数据库、网络、算法等实际领域展示累计已掌握知识、今日新增/巩固、少量下一步。今天没有新增绿色也如实说明。绿色项目到期未复习时可标注“待复测”，不宣称永久掌握。
- 内容较多时，正文按领域概览，并将完整具体清单保存到项目内 `mastery-overview.md` 后给出链接。该文件是从学习记录生成的展示结果，不是另一份独立掌握数据；每次收尾重新生成并标注日期，不能反向覆盖学习记录。
- 最后给一句简短、温暖的鼓励，肯定真实投入、坚持或具体改进，不因未全答对而否定努力。鼓励只出现一次，不额外追加测验或连续追问。
- 时长仅引用用户明确提供的实际时长或已获认可的计时记录；不得用计划时长、聊天跨度或助手执行时长推断专注学习时间。多个记录可能重叠时不盲目累加；仅知道本轮时间就说“这一轮”，不能称全天总时长。没有时长时省略分钟数，不为生成鼓励强制追问。
- 有时长且实际完成时的示例：“今天你学习了40分钟，还把一个卡点解释清楚了，做得很好，继续保持！”未知时长时的示例：“今天你认真完成了这轮复习，每一次纠错都在帮你打牢基础，继续加油！”示例中的完成情况、数量与改进必须替换为真实证据，不可直接套用。
