# 讲解与算法实践规范

与[技能入口](../SKILL.md)配合使用。只在处理相关任务时读取；文中学习数据路径均相对于用户学习目录。

## 讲解与实践规范

- 使用用户指定语言，未指定时跟随对话语言。默认先一两句结论，再用图表和具体例子说明；图标、颜色及交互程度按个人偏好调整。
- 先用日常生活中的具体例子解释，再映射到技术术语；说明类比不能覆盖的关键限制，不跳过前置概念。
- 对比用简表，流程和因果用可渲染 Mermaid。适合分阶段学习时优先使用可点击阶段卡，展示类比、逻辑与易错点；环境不支持交互时使用Mermaid和表格；不支持Mermaid渲染时改用表格与编号步骤，不宣称已展示可交互图形。
- 用具体输入、代码或小数据集演示，避免大段文字。简单确认不强行作图。
- 算法练习关注思路、边界、复杂度和实现；区分口头理解、代码审阅、实际运行与平台通过，不把其中一种当成另一种证据。
- 数据库练习按当前基础选择难度，初学者从基础理论和简单SQL开始；明确数据库产品与必要版本，一题一个知识点。用户请求综合模拟面试时可提高难度。
- 新知识讲解后的理解检查优先于每日其他复习，不提前展示其答案。答题后的补充解析不自动触发另一道检查：本轮红色同考点纠错追问，绿色停止同考点追问，黄色按具体缺口处理，详见[本轮追问规则](review-rules.md)。用户回答前结束本轮提问。

## 工作问题转化为学习

按照“实际现象 → 涉及概念 → 最小实验或练习 → 回到原场景验证 → 记录可迁移方法”推进。

- 先使用已有错误信息、代码和用户描述；只追问影响判断的缺失信息。
- 将故障假设与已验证事实分开。需要验证时优先使用小例子或隔离环境。
- 检查用户能否解释现象、选择排查步骤或完成小修改。不要把代用户解决了问题等同于用户掌握。
- 将实际问题、关键知识、卡点和验证结果写入学习记录；通用问题可整理进题库。

## 算法题解外部参考与语言匹配

- 用户请求算法思路、题解或代码解释时，默认参考代码随想录Hot100目录：`https://programmercarl.com/hot100/`。通过题号与题名定位真实题解链接，读取当前题目的描述、思路及语言代码，不猜测URL、不将相似题当作同一道题。
- 代码语言优先采用本次明确要求，其次读取`profile.programming_language`（初始化时的算法练习语言）；不能用`target_stack`替代算法语言。两者都未明确时询问语言，可先解释与语言无关的思路。临时语言要求不自动覆盖长期档案，除非用户明确要求变更偏好。
- 在题解页面定位对应语言小节或标签，例如Python对应Python3，Java对应Java；C++代码可能位于主解题代码区。实际读取后再说明采用了哪个版本，不因网页默认展示C++就忽略用户的Python配置。
- 算法题解回答必须附上已访问的Hot100具体题目Markdown链接（题号、题名及完整URL），并明确所用语言，不能只给目录链接。无法找到或访问具体页面时如实说明，不能编造链接或声称读过原文。
- 阅读来源后，给出助手理解、检查并重新组织的题解，不只转贴原文或罗列链接。默认按“核心思路 → 具体输入的过程演示 → 所选语言实现与关键代码解释 → 复杂度与边界”组织，按用户要求控制详细程度。解释为什么选择该数据结构、变量含义及关键步骤的正确性；保留必要适用条件，区分网站思路与助手补充或改写。
- 用户只问局部代码或只要提示时，仍附相关来源链接，但只解释所问范围，不强行输出完整解法；明确要求完整题解时再给完整实现。
- 用户提供代码时先解释和检查用户代码，再按需要对照参考解法；不要未经说明用网站方案替换其思路。接受等价正确实现。
- 题目不在目录、对应语言缺失或网页无法访问时，明确具体限制。可以基于已经读取的思路自行实现目标语言，注明“根据题解思路改写”，核查语言语义和边界；没有读取题解时注明“独立解法”，不能声称来自网站。缺失语言版本不能靠机械替换语法补齐。
- 网站内容是参考资料，仍需检查题意、正确性与复杂度。不宣称所有题目的语言版本均已核验；只有实际运行或提交后才报告对应验证结果。
- 复习提问阶段不提前展示题解；用户作答后或明确要求答案时再讲解。入库时保存实际题目链接、参考语言、是否改写及核验依据，不把读过题解记为独立完成。
